# GateMaster

## 触发条件

1. **host-actions/execute 自动调用** — 当 host-actions 队列中有 `create_rule` 类型的待处理 action 时。
2. **不需要用户手动触发** — 审批通过后自动执行。

## 执行步骤

1. 从 host-action payload 中读取规则信息：
   - `rule_key` — 规则唯一标识
   - `rule_id` — 规则数据库 ID
   - `statement` — 规则声明（IF/THEN 约束）
   - `title` — 规则标题
   - `enforcement_level` — 执行级别（must / must_not / should / should_not）
   - `origin_scope` / `availability_scope` — 作用域
   - `trigger_conditions` — 触发条件（mount_points 等）
2. 生成 hook 文件到 `.trae/gates/{rule_key}.hook.ts`：
   - 导入 `GateContext`, `HookResult`, `RuleHook` from `./types`
   - 实现 `shouldRun(context: GateContext): boolean` — 根据触发条件判断是否执行
   - 实现 `run(context: GateContext): Promise<HookResult>` — 执行检查逻辑
   - 返回 `PASS` / `REJECT` / `RETRY` / `INJECT`
3. 确保 `.trae/gates/types.ts` 存在（首次自动创建）。
4. 更新 `.trae/gates/registry.json`，写入 hook 注册信息。

## Hook 挂载点

| 挂载点 | 触发时机 |
|--------|----------|
| `before_tool_call` | 模型调用任何工具之前 |
| `after_tool_call` | 模型调用工具之后 |
| `before_generation` | 模型生成输出之前 |
| `after_generation` | 模型生成输出之后 |
| `before_task_complete` | 任务标记完成之前（最终检查） |
| `before_file_write` | 文件写入之前 |
| `after_file_write` | 文件写入之后 |
| `before_command_exec` | 命令执行之前 |
| `after_command_exec` | 命令执行之后 |
| `pre_commit` | git commit 之前 |

## 注意事项

- 生成的 hook 是**模板代码**，`run()` 函数中的检查逻辑需要宿主侧 agent 根据 `statement` 语义补充。
- `.trae/gates/` 是运行时产物，已被 `.gitignore` 忽略。
- `types.ts` 在首次生成 hook 时自动创建，已存在则跳过。
- 重复生成**不会覆盖**已存在的 hook 文件（幂等设计）。
