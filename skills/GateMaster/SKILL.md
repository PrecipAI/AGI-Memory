# GateMaster

## 触发条件

1. **host-actions/execute 自动调用** — 当 host-actions 队列中有 `create_rule` 类型的待处理 action 时。
2. **不需要用户手动触发** — 审批通过后自动执行。

## 核心原则（重要）

**生成的 hook 必须是可执行的，不是模板代码。**

- ❌ 旧做法：生成 `return { action: "PASS" }` 空壳，让"宿主 agent 补充逻辑"——没人补，hook 永远是死的。
- ✅ 正确做法：`buildHookFile` 根据 rule 的 `category`（test_discipline/code_format/sensitive_info/env_check 等）生成**真实检查逻辑**。
- ✅ 必须确保 runtime + 触发器就位：`scripts/gate-runtime.mjs`（执行器）+ `.git/hooks/pre-commit`（git 触发器）。

hook 文件 + runtime + 触发器 = 完整门控链路，三者缺一不可。

## 执行步骤

1. 从 host-action payload 中读取规则信息：
   - `rule_key` — 规则唯一标识
   - `rule_id` — 规则数据库 ID
   - `statement` — 规则声明（IF/THEN 约束）
   - `title` — 规则标题
   - `enforcement_level` — 执行级别（must / must_not / should / should_not）
   - `origin_scope` / `availability_scope` — 作用域
   - `trigger_conditions` — 触发条件（mount_points 等）
2. **生成 hook 文件**到 `.trae/gates/{rule_key}.hook.ts`：
   - 导入 `GateContext`, `HookResult`, `RuleHook` from `./types`
   - 实现 `shouldRun(context: GateContext): boolean` — 根据 applies_to + trigger_conditions 判断是否执行
   - 实现 `run(context: GateContext): Promise<HookResult>` — **真实检查逻辑**，根据 category 分派：
     - `test_discipline` — 检查代码改动是否伴随测试文件改动，无则 REJECT
     - `code_format` — 调 `npx prettier --check` 检查代码格式
     - `sensitive_info` — 检查 diff 中是否含密钥/token 模式
     - `env_check` — 检查 .env 文件是否齐全
     - `dependency_license` — 检查 package.json 依赖 license
     - 其他 category — 通用 statement 匹配检查
   - 返回 `PASS` / `REJECT` / `RETRY` / `INJECT`
3. 确保 `.trae/gates/types.ts` 存在（首次自动创建）。
4. 更新 `.trae/gates/registry.json`，写入 hook 注册信息（rule_key/mount_points/file/enabled）。
5. **确保 runtime 就位**（关键，旧版缺失）：
   - 确认 `scripts/gate-runtime.mjs` 存在 — hook 执行器，加载 .hook.ts + 构造 GateContext + 执行 + REJECT 退出
   - 确认 `scripts/install-gate-hooks.mjs` 存在 — 安装 .git/hooks/pre-commit 调 runtime
   - 首次安装或 runtime 文件更新后，运行 `node scripts/install-gate-hooks.mjs` 把触发器装到 .git/hooks/

## 门控链路（三层缺一不可）

```
┌─────────────────────────────────────────────────────────────┐
│  rule 审批通过 → host-action: create_rule                   │
│                          ↓                                  │
│  GateMaster 执行                                            │
│    1. buildHookFile(payload)  → .trae/gates/{key}.hook.ts  │
│       (含真实检查逻辑，根据 category 分派)                   │
│    2. 注册到 registry.json                                  │
│    3. 确保 runtime 就位:                                    │
│       - scripts/gate-runtime.mjs    (执行器)               │
│       - scripts/install-gate-hooks.mjs (安装器)            │
│                          ↓                                  │
│  git commit                                                 │
│    → .git/hooks/pre-commit (shell)                          │
│    → node scripts/gate-runtime.mjs --mount-point=pre_commit │
│    → 加载所有 mount_points 含 pre_commit 的 .hook.ts        │
│    → 构造 GateContext (getChangedFiles/exec/git status)     │
│    → 调用 shouldRun() + run()                               │
│    → REJECT 则 exit 1 阻断 commit                           │
└─────────────────────────────────────────────────────────────┘
```

## Hook 挂载点

| 挂载点 | 触发时机 | 当前支持 |
|--------|----------|---------|
| `pre_commit` | git commit 之前 | ✅ git pre-commit hook（硬门控） |
| `before_task_complete` | 任务标记完成之前 | 🔄 待 runtime 支持 |
| `before_file_write` | 文件写入之前 | 🔄 待 runtime 支持 |
| `after_file_write` | 文件写入之后 | 🔄 待 runtime 支持 |
| `before_command_exec` | 命令执行之前 | 🔄 待 runtime 支持 |
| `after_command_exec` | 命令执行之后 | 🔄 待 runtime 支持 |
| `before_tool_call` | 模型调用工具之前 | 🔄 待 runtime 支持 |
| `after_tool_call` | 模型调用工具之后 | 🔄 待 runtime 支持 |
| `before_generation` | 模型生成输出之前 | 🔄 待 runtime 支持 |
| `after_generation` | 模型生成输出之后 | 🔄 待 runtime 支持 |

当前 `pre_commit` 已通过 git pre-commit hook 实现硬门控。其他挂载点需要宿主侧 runtime 主动调用，未来可扩展（如 trae MCP server 或 Skill）。

## 注意事项

- 生成的 hook **不是模板代码**，`run()` 函数中是真实检查逻辑，根据 rule 的 category 分派。
- `.trae/gates/` 是运行时产物，已被 `.gitignore` 忽略。
- `scripts/gate-runtime.mjs` 和 `scripts/install-gate-hooks.mjs` 是源码，**会被 git 跟踪**。
- `.git/hooks/pre-commit` 不会被 git 跟踪（.git 是 git 内部目录），所以需要 `install-gate-hooks.mjs` 安装。clone 仓库后需运行一次 `node scripts/install-gate-hooks.mjs`。
- 重复生成**不会覆盖**已存在的 hook 文件（幂等设计），但可用 `scripts/regenerate-hooks.mjs` 强制重生所有 hook。
- runtime 执行异常**不阻断**用户操作（exit 2），避免 runtime bug 卡死工作流；只有 hook 返回 REJECT 才阻断（exit 1）。

## 验证 hook 生效

生成或更新 hook 后，运行以下命令验证：

```bash
# 1. 安装 git pre-commit 触发器（首次或 runtime 更新后）
node scripts/install-gate-hooks.mjs

# 2. 手动触发一次 pre_commit 门控检查（不真的 commit）
node scripts/gate-runtime.mjs --mount-point=pre_commit

# 3. 真实 commit 测试（会被 hook 拦截）
git add some_file_without_test
git commit -m "test"   # 应该看到 REJECT
```
